# 『はなむけ』 制作指示書（作品ID：kadv14）

このフォルダは、共通エンジンテンプレート（ゲームオーバー機能の改修済み）を複製したものです。
ここに、選択肢型テキストADV『はなむけ』を作ってください。

## 0. 最初に読むもの（この順番で）

1. `README.md`（テンプレートの説明。ゲームオーバー機能の節も含めて全部）
2. この指示書
3. `docs/secret/design.md`（裏設計書。物語の中身はすべてここにあります）

## 1. ネタバレ防止（最重要）

プレイヤー（結夏）は、この作品の中身を何も知らない状態で遊びます。

- **進捗報告は、技術的な事実だけにしてください。** 例：「第3章：7120字」「継ぎ目14箇所を点検、修正2件」「到達テスト：24/24 通過」。あらすじ、人物の正体、展開、台詞、場面の説明は書かないでください。
- ファイル名、コミットメッセージ、ラベル、パラメータ名、`@vis` / `@fx` / `@mark` の名前、記録とゲームオーバーの識別子、CSS クラスには、中身が推測できる語を使わないでください（`ch01`、`ed01`、`g01a`、`p1`、`r01`、`m1` などの記号にする）。対応表は `docs/secret/notes.md` にだけ書きます。
- デバッグ機能は `?debug=1` のときだけ出してください。
- 結夏が「ネタバレOK」と言うまで、このルールを解除しないでください。

## 2. 作るもの

- **作品ID：** `kadv14`（`game/config.js` の `id`）
- **タイトル：** `はなむけ`
- **全十五章**（`ch01`〜`ch15`）
- **本編エンディング六種**（`ed01`〜`ed06`）、**追加エンディング二種**（`ed07`・`ed08`。`extraUnlock: 'all-main'`）
- **ゲームオーバー十四件**（`g01`〜`g14`。すべて版A・版Bの二つのファイル。`g01a` / `g01b` …）
- **記録十件**（`r01`〜`r10`）
- ダミーのシナリオと、`config.js` の「ダミー専用」の行から下は消してください。

- 曲は追加エンディングの二本だけです（音源ファイルは結夏が自分で用意します。無くても無音で動くこと）。曲の識別子は `s1`・`s2` にします。

## 3. 文字数の目標（数値で守る）

- 本編：一章あたり分岐込みで **7000字前後**
- 本編エンディング：それぞれ **3500字前後**（場面を5〜7つに分ける）
- 追加エンディング：それぞれ **6000字前後**（場面8〜9つ）
- ゲームオーバー：**版ごとに1500字前後**
- 誤差は ±15%。各章・各エンディングを書き終えるたびに `node tools/count.js` で数え、範囲に入っていなければ場面を書き足してください。報告に「第N章：○○字」を含めてください。
- **文字数が足りないときは、心の声ではなく、会話・行動・場面を書き足してください。**

## 4. 書き方の約束

### 主人公と地の文

- 主人公（先輩）は名前入力の分身型です。**主人公の発言は、カギカッコで書かず、▷ から始まる間接話法の一文で書いてください。**
- **主人公の内面（考え・気持ち・回想）は地の文に書かないでください。** 気持ちは ▷ の行と行動で見せます。
- 地の文は三人称で、カメラは基本的に主人公の側に置きます。**後輩の目線の場面は、裏設計書で指定した場所だけ**です。そこでは `@vis` で枠を切り替えて、目線が変わったことをはっきりさせてください。心の声を書くときは、誰の考えか分かる形にしてください。
- **地の文での呼び方は、裏設計書の「呼び名の切り替え」に厳密に従ってください。** この作品では、名前が分かるまでの間、地の文で二人を「花嫁」「花婿」と呼びます。切り替えの位置より前に `{name}` や後輩の本名を地の文に出さないでください。**地の文で主人公を「先輩」と呼ばないでください。** 台詞の中の「先輩」はそのままです。

### 文体

- 一行が一回のクリックです。テンポを大事にしてください。
- 裏設計書の【書き方】の指示や、口調・温度・文体の指定は、作者への指示です。本文に書き写さないでください。台詞そのもので見せてください。地の文で登場人物の口調を実況しないでください（『敬語はそのままだった』『いつもの平らな声で』『敬語が崩れなかった』など）。例外は、口調が変わること自体が物語の転換点になる場面だけで、一作に一、二回までです。
- 次の言い回しは使わないでください：「天気の話をするみたいに」、「紙のようだった」（顔色）、「早かった。早すぎた。」型の畳みかけ。
- 短い言葉が決定打になる場面は、文字数で数えずに「その一言」と書いてください。
- 裏設計書に例として挙げた台詞や文は、方向を示す例です。文言をそのまま使わないでください。同じ締めの言い回しは、一章の中で二回まで、作品全体でも数回までにしてください。
- 登場人物は、特に理由がなければ普通に悲鳴を上げてかまいません。

### 怖さと身体の描写

- この作品は、往年のフリーホラーのような理不尽さと、即死の緊張を持つ脱出ホラーです。怖さは薄めずに書いてください。
- ゲームオーバーの版A・版Bの書き分けは、裏設計書の指定に従ってください。
- 身体が損なわれる場面では、損なわれていく過程を細かく追うより、結果、音、匂い、温度、手触り、置かれた物、見ている人の反応で見せてください。そのほうが想像で効きます。ただし、結果はぼかさずに言い切ってください。

### 恋愛の描写

- 恋愛の官能的な緊張感は歓迎です。手や指の触れ合い、近い距離、息、体温、口づけの場面は、遠慮せず、薄めず、丁寧に書いてください。口づけは『二人は口づけた。』の一文で済ませず、一つの場面として書いてください。
- 口づけの温度は、エンディングの種類で変えます（裏設計書の各エンディングに指定があります）。口づけの最中の息遣いは、地の文で済ませず、途切れた言葉そのものを台詞にしてください。息が切れても、後輩の敬語と生意気は残してください。
- 本編（第一章〜第十五章）では、どの分岐でも口づけは起こりません（エンディングのために取ってあります）。

## 5. 分岐の整合性

- 合流後の共通の文には、どの分岐から来ても成り立つことだけを書いてください。分岐ごとの出来事や状態に触れたいときは、状態に応じて差し替わる短い差し込み文（`@if`）にしてください。
- `docs/secret/notes.md` に「分岐で変わる事実の表」を持たせてください（裏設計書に初期の表があります）。
- 各章を書き終えたら `node tools/seams.js` で継ぎ目を書き出し、選択肢ごとに「分岐の文→合流後の文」の順で読み通して点検してください。
- 全部書き終えたあとの通し点検でも、分岐で変わる事実の表と本文を突き合わせてください。

## 6. 選択肢

- **選択肢の並び順は、裏設計書に書いた順のまま**にしてください（並べ替え済みです）。パラメータの種類で並び順を固定しないでください。
- 書き終えたら `node tools/choices.js` で文面の被りを点検し、同じ方向の選択肢でも場面ごとに違う言葉と角度にしてください。

## 7. 一気書きの進め方

途中で止めて確認を挟まず、最後まで一気に書いてください。そのかわり、次のことを守ってください。

1. 各章を書き始める前に、裏設計書の該当章、人物、呼び名の切り替え、伏線表、ゲームオーバー一覧を読み直す。
2. 章を書き終えるたびに `docs/secret/notes.md` に続き物のメモを追記する（置いた伏線、人物の状態、地の文での呼び方、怪我や持ち物の変化、分岐で変わる事実）。
3. 書く順番は、本編十五章 → ゲームオーバー十四件（版A・版B） → 本編エンディング六種 → 追加エンディング二種 → 記録十件。
4. 全部書き終えたら通しで点検する：伏線がすべて回収されているか、人名・呼び方・口調の揺れ、地の文の呼び名の切り替え位置、分岐の整合性、選択肢の文面の被り、選択肢の並び順。

## 8. 点検とテスト（全部通すこと）

- `node tools/count.js`：文字数がすべて範囲内であること。
- `node tools/tone.js`：地の文の「敬語」「口調」「声で」「調子で」を一覧にし、実況になっている行を削るか書き換える。
- **地の文の呼び名の点検：** スクリプトで、カギカッコと▷の行の外にある `{name}`・後輩の本名・「先輩」を、ファイル名と行番号つきで書き出してください。裏設計書の切り替え位置より前に `{name}` や本名が出ていないこと、地の文に「先輩」が出ていないことを確かめてください。
- **締めの言い回しの点検：** ゲームオーバーと山場の締めの文を一覧にして、言い回しの偏りを直してください。
- `node tools/reach.js`：本編エンディング六種すべてに通常プレイで到達できること。ゲームオーバー十四件すべてに到達できること。`@altopen` に到達できること。
- `tests/`：本編エンディングごとのルート（`route_ed01.js`〜`route_ed06.js`）、追加エンディング（`route_ed07.js`・`route_ed08.js`）、ゲームオーバーごとのルート（本編で流れる版で、`route_g01a.js` など十四本）、`over_list.js`。`node tests/run_all.js` が全部通ること。
- 到達条件は裏設計書のとおりです。数値の最大値・最小値を計算して、通常プレイで全部到達できることを確かめてください。

## 9. 完成時の報告

技術的な事実だけを報告してください。

- 各章・各エンディング・各ゲームオーバー（版A・版B）の文字数
- 点検スクリプトの結果（継ぎ目の点検数と修正数、口調の実況の修正数、呼び名の点検結果、選択肢の被りの修正数）
- テストの結果（「到達テスト：N/N 通過」）
- 裏設計書にない要素を足した場合は、`docs/secret/notes.md` の「足したもの」の節に書いておいてください（報告には中身を書かない）。
