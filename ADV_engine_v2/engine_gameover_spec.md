# エンジンテンプレート改修指示書：途中ゲームオーバーと一覧（任意機能）

対象：`ADVのエンジンテンプレートREADME.md` の共通エンジンテンプレート（`adv-engine/`）

## 0. この作業の範囲

- **テンプレートの改修だけを行う。作品のシナリオは書かない。**改修と点検とテストが終わったら、そこで止めて報告すること。次の指示が来るまで作品の作業には入らない。
- 追加する機能は**任意機能・初期状態はオフ**とする（記録機能と同じ扱い）。オフのままなら、既存の作品の動作が一切変わらないこと。
- エンジン本体（`engine/`）の改修は、他の作品でも使い回す前提で、**特定の作品の内容を前提にしない汎用の作り**にする。
- 既存のルールは全部そのまま守る：本文のテキストボックス（`#box`）と文字（`#lines`）は揺らさない、保存は作品IDを頭に付ける、読み書きは try/catch、`?debug=1` のときだけデバッグ欄、など。

---

## 1. 追加する機能の概要

1. **途中ゲームオーバー**：本編の途中で、エンディングとは別枠の「ゲームオーバー」に入れる。終わったら「直前の選択肢からやり直す」で戻れる。
2. **ゲームオーバー一覧**：回収したゲームオーバーが溜まる一覧。エンディング一覧とは別。未回収は「？？？」、回収済みは再生できる。
3. **二つの版**：ゲームオーバー一つにつき、版A・版Bの二つの中身を持てる。
4. **版の切り替え**：条件を満たすと、一覧での再生が版Bに切り替わる。切り替え後は、一覧のボタンで版Aと版Bを行き来できる。

## 2. 設定（game/config.js）

```js
gameovers: {
  enabled: false,              // 初期値オフ
  label: 'ゲームオーバー一覧',   // タイトル画面・メニューに出る一覧の名前
  screenText: 'GAME OVER',     // ゲームオーバー画面に出す文字
  retryLabel: '直前の選択肢からやり直す',
  list: [
    // id: 識別子（g01, g02 … の記号）
    // a: 版Aのファイル名 / b: 版Bのファイル名（省略可。無ければ版Aを使う）
    // title: 一覧に出す名前（未回収のあいだは「？？？」）
    { id: 'g01', a: 'g01a', b: 'g01b', title: '見出し' },
  ],
  alt: {
    enabled: false,            // 版の切り替えを使うか
    toA: '版Aを見る',           // 切り替え後、版Aに戻すボタンの文言
    toB: '版Bを見る',           // 版Aを見ているとき、版Bに戻すボタンの文言
  },
},
```

- 文言はすべて作品ごとに変えられること。テンプレートの初期値は上のような**中立な言葉**にする。
- `list` の各ファイルは `config.files` にも並べる（読み込みの仕組みは既存のものを使う）。
- 設定の点検（loader.js）：`enabled: true` なのに `list` が空、`a` のファイルが無い、識別子が重複、などは起動時に分かるエラーにする。

## 3. シナリオの命令

| 書き方 | 意味 |
|---|---|
| `@gameover g01` | 版Aのファイルへ移り、その末尾でゲームオーバー画面へ。回収記録が付く |
| `@gameover g01 b` | 同じく、版Bのファイルを使う |
| `@altopen` | 版の切り替えを解放する（一度解放したら、新しく始めても解放されたまま） |

- **本編中にどちらの版を流すかは、シナリオ側が `@gameover` の書き方で決める。**一覧の切り替え状態では決めない（一度解放したあと「はじめから」遊んでも、本編の序盤は序盤の版のまま流れるようにするため）。
- ゲームオーバーのファイルは、エンディングと同じく1ファイルで完結させ、最後は新しい命令 `@over` で終える（`@end` とは区別する。`@over` の無いゲームオーバーのファイルは「本文が途切れています」エラー）。
- 機能がオフのときに `@gameover` / `@altopen` / `@over` を書いたら、読み込み時に分かるエラーにする。
- `@gameover` のファイル内でも `{name}`、`@vis`、`@fx`、`@bgm`、`@mark` などの既存の命令は使える。

---

## 4. ゲームオーバー画面とやり直し

- ゲームオーバーのファイルを読み終えたら、`screenText` を出す画面へ移る。ボタンは二つ：
  - **`retryLabel`（直前の選択肢からやり直す）**：直前の選択肢セーブ（`ID.qsave`）をロードする。ロードと同じ扱いなので、曲はフェードして止まる。
  - **タイトルへ**
- 直前の選択肢セーブがまだ無い場合（選択肢が一度も出ていない位置でのゲームオーバー）は、やり直しは「はじめから」と同じ動きにする。
- **ゲームオーバーの記録は、ゲームオーバー画面に着いた時点ではなく `@gameover` に入った時点で付ける**（途中でタイトルに戻っても回収済みになる）。版A・版Bのどちらで到達しても同じ識別子の回収として扱う。
- スキップ中にゲームオーバーに入ったら、未読と同じく止まること。既読の判定は既存の仕組みのまま（ゲームオーバーのファイルも既読対象）。
- ゲームオーバーはセーブ一覧の「位置」として保存できなくてよい（ゲームオーバーのファイル中は手動セーブを押せなくする）。

---

## 5. 一覧と版の切り替え

- タイトル画面とメニューに `label` の項目を足す（`enabled: true` のときだけ）。
- 一覧は `list` の順に並べる。未回収は「？？？」、回収済みは `title`。回収数（例：3 / 12）を見出しに出す。
- 回収済みを選ぶと、そのゲームオーバーを単体で再生する。再生が終わったら、ゲームオーバー画面ではなく一覧に戻る。名前は前回入力した名前を使う（エンディング再生と同じ扱い）。
- **版の切り替え（`alt.enabled: true` のとき）：**
  - `@altopen` に一度も到達していないあいだは、一覧の再生は**版Aだけ**。**切り替えボタンは出さない**（存在が分からないようにする）。
  - 解放後は、一覧の再生は**版Bが基本**になり、一覧の画面に切り替えボタンが出る。
    - 版Bを見ている状態のボタンの文言：`alt.toA`
    - 版Aを見ている状態のボタンの文言：`alt.toB`
    - 押すたびに一覧全体の表示版が入れ替わる。どちらを見ているかは一覧の画面で分かるようにする（ボタンの文言で分かれば十分）。
  - `b` の無い項目は、どちらの状態でも版Aを再生する。
  - 一覧で再生した版も、既読の判定は既存の仕組みのまま。

## 6. 保存

既存の表に足す。

| 名前 | 中身 | 消えるとき |
|---|---|---|
| `ID.overs` | ゲームオーバーの回収記録 | セーブとは別 |
| `ID.alt` | 版の切り替えの解放 | セーブとは別 |
| `ID.altView` | 一覧でいまどちらの版を見ているか | セーブとは別 |

## 7. 演出の差し込み口（game/effects.js）

既存の差し込み口に足す（全部省略可）。

| 名前 | 呼ばれるとき |
|---|---|
| `onGameover(id, ver, ctx)` | `@gameover` に入ったとき（`ver` は `'a'` か `'b'`） |
| `onOverScreen(id, ver, ctx)` | ゲームオーバー画面を出したとき |
| `onAltOpen(ctx)` | `@altopen` に初めて到達したとき |

`ctx` に `replaying`（一覧からの再生中なら true）を足す。ゲームオーバー画面の見た目は `game/theme.css` で上書きできるよう、要素にクラスを付けておく。

## 8. デバッグ（?debug=1 のときだけ）

- ゲームオーバーを全回収／回収の消去
- 版の切り替えを解放／解放の消去
- 一覧の表示版の表示
- `@gameover` の行へ移動できるよう、既存の「ファイルを選んで移動」の候補にゲームオーバーのファイルも入れる

## 9. 点検用スクリプトとテスト

- **reach.js**：`@gameover` を行き止まりとして扱い、各ゲームオーバーに通常プレイで到達できるかを報告する（到達できるものは選び方の例と `picks` を表示）。`list` にあるのに到達できないもの、版Bが一度も使われない項目、`@altopen` に到達できるかも報告する。エンディングの到達確認は従来どおり。ゲームオーバーで行き止まりになる選択肢を除いても、各本編エンディングに到達できることを確かめる。
- **count.js**：ゲームオーバーのファイルも数える。目標は `config.tools.targets.gameover`（初期値 1500字、±15%）。版Aと版Bは別々に報告する。
- **seams.js / choices.js / tone.js**：ゲームオーバーのファイルも対象に含める。
- **テスト**：`tests/lib` にゲームオーバー用の補助を足す（例：`overRoute({ go: 'g01', ver: 'a', picks: [...] })`）。一覧での再生、版の切り替えの解放前後の再生版、ボタンの出し分けを確かめるテストも作る。
- テンプレート同梱のダミーシナリオに、ゲームオーバーを一つ（版A・版Bあり）と `@altopen` を一か所足し、上の点検とテストがすべて通る状態にする。**ダミーの設定では `enabled` をオンにして動作確認し、テンプレートとして渡す状態では初期値オフに戻す**（ダミーの動作確認のやり方は README に書く）。
