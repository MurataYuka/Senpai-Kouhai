# CLAUDE.md　作品『かえりみち』制作指示書（表）

選択肢型テキストADV『かえりみち』を、共通エンジンテンプレート（`adv-engine`）で作ります。
この指示書にはネタバレを書いていません。物語の中身はすべて `docs/secret/` にあります。

---

## 1. 最初にやること

1. `adv-engine` テンプレートを丸ごとこのフォルダにコピーする（`docs/` は上書きしない）。
2. テンプレートの `README.md` を読む。書式・命令・点検スクリプトはそれに従う。
3. `docs/secret/` の四つを全部読む。
   - `design.md`（世界・真相・人物・仕掛け・パラメータ・到達条件・演出）
   - `chapters.md`（全十五章の構成と選択肢）
   - `endings.md`（エンディング八種）
   - `opening.md`（冒頭の一場面。第一章の頭にそのまま使う）
4. `game/config.js` を設定する。
   - `id: 'kaerimichi'`
   - `title: 'かえりみち'`
   - `files`：`ch01`〜`ch15`、`ed01`〜`ed08`、`records`
   - `vars`：`p1` `p2` `p3`（0〜40）、`f1`（0〜1）
   - `endings.main`：`ed01`〜`ed06`。`endings.extra`：`ed07` `ed08`、`extraUnlock: 'all-main'`
   - `records.enabled: true`（画面での名前は「記録帳」）
   - `bgm`：初期値のまま。音源は `assets/bgm/m1`（無くても無音で動くこと）
5. `docs/secret/notes.md` を作る（下の 5）。

---

## 2. ネタバレ防止（結夏が「ネタバレOK」と言うまで解除しない）

- 結夏はこの作品の中身を知らずに遊びます。
- **進捗報告は技術的な事実だけ**にする。例：「第三章：7120字」「第五章：継ぎ目6箇所を点検、修正1件」「到達テスト 8/8 通過」。あらすじ、登場人物の行動、場面の説明、感想は書かない。
- ファイル名・選択肢ID・ラベル・パラメータ名・`@vis` `@fx` `@mark` の名前・記録の識別子・CSS クラス・コミットメッセージに、内容が推測できる語を使わない（`ch01`、`ed01`、`p1`、`v1`、`r01`、`m1` などの記号にする）。
- エンディングの題名は、到達したときに画面に出るだけにする。一覧では未回収を「？？？」にする。
- デバッグ機能は `?debug=1` のときだけ。
- 質問があるときも、中身に触れずに聞く（「第○章の△△の扱いについて、裏設計書の記述が二通りに読めます」くらいまで）。

## 3. 書き方の進め方

- **一気書き**。途中で止めて確認を挟まない。
- 各章を書き始める前に、`docs/secret/` の該当章・登場人物・伏線表・`notes.md` を読み直す。
- 章を書き終えるたびに：
  1. `node tools/count.js` で文字数を数える。目標の ±15% に入っていなければ、足りない場面を書き足す（削って合わせるより、場面を足す）。
  2. `node tools/seams.js chNN` で継ぎ目を書き出し、選択肢ごとに「分岐の文 → 合流後の文」の順で読み通して点検する。
  3. `docs/secret/notes.md` に続き物のメモを追記する。
  4. 報告は「第N章：○○字、継ぎ目○箇所を点検、修正○件」だけ。
- 全章と全エンディングを書き終えたら、通しで点検する（下の 7）。

### 文字数の目標
- 本編：一章あたり分岐込みで **7000字前後**。
- 本編エンディング（ed01〜ed06）：それぞれ **3500字前後**。場面を五〜七つに分ける。種類を問わず同じ長さと密度にする。
- 追加エンディング（ed07・ed08）：それぞれ **6000字前後**。場面は八〜九つまで。

## 4. 本文の書き方

### 裏設計書の読み方
- 裏設計書の【書き方】と頭についた行、口調・温度・文体の指定は、作者への指示です。**本文に書き写さないでください。** 台詞そのもので見せてください。
- 地の文で登場人物の口調を実況しない（「敬語はそのままだった」「いつもの平らな声で」「敬語が崩れなかった」など）。例外は、口調が変わること自体が物語の転換点になる場面だけで、一作に一、二回まで。
- 裏設計書の台詞の例は方向を示すもの。文言はそのまま使わず、場面ごとに作る。

### 主人公と後輩
- 主人公（先輩）は名前入力の分身型。本文では `{name}`。**主人公の発言はカギカッコで書かず、▷ から始まる間接話法の一文で書く。**
- 後輩は眼鏡、年下、敬語、生意気。主人公を「先輩」と呼ぶ。生意気は理屈っぽい強がりと素直になれなさで、毒舌ではない。
- 登場人物は、特に理由がなければ普通に悲鳴を上げてよい。後輩も上げる。

### 選択肢
- 選択肢は `chapters.md` に書いた **並び順のまま** データに書く。表示のたびに並べ替えない。
- 選択肢の文面が、別の章の選択肢と被らないようにする。

### 分岐の整合性
起きやすい不具合は二つ。
1. 選ばなかった選択肢の中身が、合流後の共通の文に混ざる。
2. 分岐ごとに違う状態が、合流後の共通の文で食い違う。

- 合流後の共通の文には、どの分岐から来ても成り立つことだけを書く。分岐ごとの出来事や状態に触れたいときは、`@if` の短い差し込み文にする。
- 分岐のあとに残る状態は `design.md` の「状態」の表にあるものだけ。それ以外は分岐の中で完結させる。

### 描写について
- 恋愛の官能的な緊張感は歓迎です。手や指の触れ合い、近い距離、息、体温、口づけの場面は、遠慮せず、薄めず、丁寧に書いてください。口づけは「二人は口づけた。」の一文で済ませず、一つの場面として書いてください。
- 口づけの最中の息遣いは、地の文の「息が乱れた」で済ませず、途切れた台詞そのもので見せてください。後輩の敬語と生意気は、息が切れても残してください。同じ台詞の型を作中で繰り返さないでください。
- 口づけの温度はエンディングの種類で変える（`endings.md` の指定に従う）。
- 身体が損なわれる場面は、直接の描写より、暗転、時間の経過、物音、置かれた物、口元、涙、声で見せるほうが想像で効きます。
- 短い言葉が決定打になる場面は、文字数で数えず「その一言」と書く。
- 作品をまたいで頻出する言い回しを使わない：「天気の話をするみたいに」、「紙のようだった」（顔色）、「早かった。早すぎた。」型の畳みかけ。

### 地雷（これだけは避ける）
- 腹黒な後輩（後輩が加害的・計算高く見える書き方）。
- 主人公が後輩を見下す・支配する形。
- 乙女ゲームの小悪魔系年下（可愛い寄りの「素直じゃないねぇ♡」になるタイプ）。
- 毒舌キャラ。

## 5. `docs/secret/notes.md`（非公開の続き物メモ）

章を書き終えるたびに追記する。最初に次の二つの表を作っておく。

- **分岐で変わる事実の表**：状態の記号、立つ章、各章での書き分け（`design.md` の「状態」から写す）。
- **記号の対応表**：`p1`〜`p3`、`f1`、`v1`〜`v3` とその値、`r01`〜`r10`、`m1`。

毎章の追記：その章で置いた伏線、人物の状態（怪我、持ち物、呼び方、関係の温度）、分岐で変わる事実。

## 6. 画面・システム

- テンプレートの標準仕様（手動セーブ 11、直前の選択肢セーブ、エンディング再生、スキップ、記録、音量と消音）をそのまま使う。
- **本文のテキストボックスと文字は揺らさない。** 揺れ・傾き・明滅は枠と背景だけ。大きな演出はテキストボックスの **後ろ**（`#back` / `#fxLayer`）でやる。
- 枠・背景・演出の中身は `design.md` の 8 に従う。`game/theme.css` と `game/effects.js` に書く。
- 曲は `@bgm m1` の一か所だけ。音源ファイルが無くても無音で最後まで動くこと。

## 7. 仕上げの点検（全部書き終えたあと）

1. `node tools/count.js`：全章・全エンディングが目標の ±15% に入っている。
2. `node tools/seams.js`：全継ぎ目を通しで読み、`notes.md` の分岐で変わる事実の表と本文を突き合わせる。
3. `node tools/tone.js`：地の文の「敬語」「口調」「声で」「調子で」を一覧にし、口調の実況になっている行を削るか書き換える。
4. `node tools/choices.js`：選択肢の文面の被りを確認し、似ている組を書き分ける。
5. `node tools/reach.js`：全エンディングに通常プレイで到達できることを確認する（パラメータの最小値・最大値も確認）。
6. `tests/`：エンディングごとのモデルルートを作り（`design.md` の「モデルルート」を使う。本編六本、追加二本）、`node tests/run_all.js` を通す。
7. 伏線表（`chapters.md` の最後）の全項目が回収されているか、人名・呼び方・口調の揺れがないかを確認する。
8. 頻出の言い回し（4 の最後の三つ）が本文に無いかを検索する。

報告は技術的な事実だけ：「文字数：範囲外 0件」「口調の実況 ○件を修正」「選択肢の被り ○組を修正」「到達テスト 8/8 通過」など。
