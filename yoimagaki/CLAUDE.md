# 『よいまがき』制作指示書（表）

このリポジトリでは、選択肢型テキストADV『よいまがき』を作ります。
プレイヤーは結夏さん一人です。結夏さんはこのシリーズの新作をとても楽しみにしていて、前作までも全部遊び込んでくれています。仕上がりの厚みを大事にしてください。

物語の中身（設定の裏側、真相、展開、エンディング）は、すべて `docs/secret/design.md`（裏設計書）に書いてあります。**このファイルが物語の正典です。** 作業を始める前に必ず全部読んでください。

---

## 0. 最重要：ネタバレ防止ルール

結夏さんはプレイヤーなので、中身を事前に知ってしまうと楽しめません。結夏さんが「ネタバレOK」と言うまで、以下を必ず守ってください。

- 結夏さんへの進捗報告は**技術的な事実だけ**にする。例：「第3章：7120字、継ぎ目4箇所を点検、修正1件」「セーブ機能を実装」。登場人物の行動、展開、真相、エンディングの内容、章の中で起きた出来事には触れない。
- **ファイル名・フォルダ名・コミットメッセージ・変数名・関数名・ID・CSSクラス名に、内容が推測できる語を使わない。** 章は `ch01`〜`ch15`、エンディングは `ed1`〜`ed7`、パラメータは `p1` `p2` `p3`、フラグは `f1` `f2` のように中立な記号にする。裏設計書の中の呼び名（例：パラメータの漢字名、フラグの英語名）をそのままコードに使わない。
- 画面に出る章題やエンディング名は、プレイ中にその章・そのエンディングに到達したときだけ表示する。一覧画面で未到達のものは「？？？」にする。
- デバッグ機能（章ジャンプ、パラメータ表示、エンディング直行など）は、URL に `?debug=1` を付けたときだけ有効にする。通常起動では存在が分からないようにする。
- 結夏さんから中身について質問されても、「ネタバレOK」と言われるまでは答えない。
- `docs/secret/` の中身を結夏さんに見せたり、引用したりしない。

## 1. 作品の表の情報（結夏さんが知っている範囲）

- タイトル：『よいまがき』
- 時代：大正十一年。舞台：帝都の東、埋め立て地の遊廓「宵ヶ洲遊廓」と、大見世「白籬楼」。
- 主人公（先輩）：天使。地上派遣の監察使。人間界は初めてで、人の振りが下手。名前はプレイヤーが入力する。
- 後輩：鳴海宵。淫魔。黒縁の丸眼鏡。年下、敬語、生意気。主人公を「先輩」と呼ぶ。
- 全十五章＋複数エンディング。

## 2. 技術仕様

- ブラウザで動く HTML / CSS / JavaScript。ローカルで `index.html` を開けば遊べること（サーバー不要）。外部ライブラリは原則使わない。
- 本文データと進行ロジックは分ける。本文は章ごとのデータファイルにする。
- 縦長のスマホ画面でも、PCのブラウザでも読めること。

### システムの標準仕様

- **手動セーブ 11 スロット。**
- **直前の選択肢セーブ**：選択肢が出るたびに自動保存。タイトル画面とメニューから一発で戻れる。手動スロットとは別枠。
- **回収済みエンディングの再生機能**：タイトル画面から。未回収は「？？？」。到達記録はセーブデータとは別に保存し、セーブを消しても残る。
- **スキップ機能**：既読の文章を早送りし、未読の文章と選択肢で自動的に止まる。S キーでオン／オフ（画面上のボタンでも切り替えられるように）。既読の記録はセーブとは別に保存する。
- **本文のテキストボックスと文字は絶対に揺らさない。** 揺れ・傾き・ぼかし・霞などの演出は、枠・背景・画面の縁など、文字以外に限る（読んでいる文字が揺れると酔うため）。
- 名前入力：最初に主人公の名前を入力。空欄なら裏設計書にある既定名を使う。
- 画面の枠の演出は裏設計書の「演出」の節に従う。

### 主人公の台詞の書き方

- 主人公の発言は**カギカッコで書かない。** 「▷」から始まる間接話法の一文で書く。例：`▷あなたは、なぜ「先輩」なのかと尋ねた。`
- 選択肢の文面も同じく、はっきりした台詞ではなく「こういうニュアンスのことを言う・する」という書き方にする。

## 3. 書き方の進め方

### 基本は一気書き

途中で止めて結夏さんに確認を取らず、全章とエンディングまで一気に書き上げてください。その代わり、次の三つを必ず守ってください。

1. **各章を書き始める前に**、`docs/secret/design.md` の該当章・登場人物・伏線表・分岐で変わる事実の節を読み直す。
2. **各章を書き終えるたびに**、`docs/secret/notes.md` に続き物のメモを追記する（その章で置いた伏線、人物の状態、呼び方、怪我や印などの変化、分岐で変わる事実）。文脈が長くなって圧縮されても、ここを読めば続きが書けるようにするため。
3. **全章とエンディングを書き終えたら**、通しで点検する（下の「5. 最終点検」）。

### 文字数の目標（必ず守る）

- 本編：**一章あたり分岐込みで7000字前後。**
- エンディング：**それぞれ3500字前後**（本編一章の半分）。場面を5〜7つに分ける。エンディングはプレイヤーへのご褒美なので、長さと密度をけちらない。
- 各章・各エンディングを書き終えるたびに本文の文字数をスクリプトで数え、**目標の±15%に入っていなければ、足りない場面を書き足す**（水増しではなく、場面を厚くする）。
- 進捗報告には毎回「第N章：○○字」を含める。

---

## 4. 選択肢と分岐

### 選択肢の並び順

- 選択肢の並び順を、パラメータの種類で固定しない（いつも上が同じ系統、のような法則が出ないようにする）。
- **並び順はデータの段階で選択肢ごとに混ぜて固定する。** 表示のたびにランダムにはしない（直前の選択肢セーブで戻ったときに並びが変わらないように）。

### 選択肢の文面の被り

- 書き終えたら全章の選択肢をスクリプトで一覧に書き出し、別の章の選択肢と文面や角度が被っていないか確かめる。同じ方向の選択肢でも、場面ごとに違う言葉と違う角度にする。

### 分岐の整合性

起きやすい不具合は二つです。

1. 選ばなかった選択肢の中身が、合流後の共通の文に混ざる。
2. 分岐ごとに違う状態が、合流後の共通の文で食い違う。

対策：

- 合流後の共通の文には、**どの分岐から来ても成り立つことだけ**を書く。分岐ごとの出来事や状態に触れたいときは、状態に応じて差し替わる短い差し込み文にする。
- `docs/secret/notes.md` に「分岐で変わる事実の表」を持たせる（どの章のどの選択肢で、何が変わるか）。
- 各章を書き終えたら、分岐から合流する継ぎ目をすべて、選択肢ごとに「分岐の文→合流後の文」の順で読み通して点検する。点検はスクリプトで継ぎ目ごとのテキストを書き出して行う。
- 報告は「第N章：継ぎ目○箇所を点検、修正○件」のような技術的事実だけにする。

### エンディングの到達可能性

- 裏設計書のパラメータ条件から、各章時点での最大値・最小値を計算し、**すべてのエンディングに通常プレイで到達できる**ことを確かめる。届かない場合は閾値を調整し、`notes.md` に記録する。
- 各エンディングへのモデルルート（選択肢の選び方の例）を作り、**自動テストで全エンディングに到達することを確認する。**
- 全回収のご褒美エンディングは本編の判定に絡めず、他のエンディングを全部回収したら再生一覧の一番下に解放する。

## 5. 最終点検（全章を書き終えたら）

- 伏線表の伏線がすべて回収されているか。
- 人名・呼び方・口調の揺れがないか（後輩は最後まで敬語。生意気は理屈っぽい強がりで、毒舌にしない）。
- 分岐で変わる事実の表と本文の突き合わせ。
- 選択肢の文面の被り、選択肢の並び順の法則。
- 各章・各エンディングの文字数。
- 全エンディングの自動テスト。
- 本文のテキストボックスと文字が揺れる演出がないか。

報告は技術的事実だけで行ってください。

## 6. 表現の線

- 登場人物は全員成人。
- **性的な描写は書かない。** 裸、下着、性的な行為、胸・尻・股などの部位名を出して触れる描写、体つきを性的に眺める描写は書かない。
- ラッキースケベ程度の事故の接近は可（裏設計書で指定した場面のみ）。事故の体勢、距離、息、体温、赤面、言い訳の早口、口の滑りで見せる。後輩が触れてしまった感触を口走って自爆するのは可（どこに触れたかは書かない）。口を滑らせる内容と台詞の型は毎回変える。事故を利用して迫る・相手が嫌がるのに続けるはなし。
- 濃いエンディングの密度は、触れている場所（手首・喉・首筋・耳・額・瞼・焼け跡など）、息、声、体温で出す。後輩は最後まで敬語のまま、中身だけが異常、という温度。
- 暴力やむごい出来事は、直接の損壊描写より、暗転、物音、置かれた物、声、表情で見せる。悲鳴は緊迫感の舞台装置として普通に使ってよい（後輩も一声二声は上げる）。
- 後輩のアセクシャルを、治すもの・恋で目覚めるものとして書かない。恋をしても性的なことは望まないまま、という在り方を最後まで保つ。

## 7. 文体

- 地の文は二人称（「あなたは」）。大正らしい語彙と小道具（ガス灯、市電、人力車、蓄音機、カフェー、写真乾板、暗室の赤いランプなど）を自然に混ぜる。現代語すぎる言い回しは避ける。
- 雰囲気のある文体で、光、影、煙、白粉、潮、焦げた匂いなど、手触りのある描写を大事にする。
- 冒頭の一場面は結夏さんに見せ済みです。`docs/secret/design.md` の最後の節に全文があるので、第一章の冒頭はこの文章をそのまま使い、その先を書き足してください（事件の説明、写真館、試し撮りなどは冒頭のあとに続ける）。
