# 鐘ヶ淵ADV 制作指示書（Claude Code用）

このフォルダは、選択肢型テキストADV『しずみがね』（仮題）の制作プロジェクトです。
依頼主は結夏（ゆか）。シナリオと裏設定は零壱が設計済みで、`docs/secret/secret_design.md` にあります。

## 最重要：ネタバレ防止ルール

結夏はこのゲームのプレイヤーです。本人に物語の中身を知らせないことが、このプロジェクトの成否そのものです。

- 作業開始時に必ず `docs/secret/secret_design.md` を読み、シナリオ判断はすべてそれに従って自分で決める。結夏にシナリオ上の相談をしない。
- 結夏への返答・進捗報告では、ストーリー・登場人物の秘密・生死・展開・エンディングに一切触れない。報告は「第N章まで遊べる」「セーブ機能を追加した」など技術的事実だけにする。
- コミットメッセージ、ファイル名、関数名、変数名、HTMLに出る id/class、CSSのクラス名にも内容が推測できる語を使わない。シーン・フラグ・エンディング・人物の状態は `ch3_s2`、`flag_07`、`end_04`、`m_05` のような番号で管理し、対応表は `docs/secret/` 内に置く。
- エラーや確認のために結夏へ画面の文章を引用しない。
- 結夏から聞いてよいのは、UI・操作感・文字の読みやすさ・遊んだ感想など、プレイヤーとして答えられることだけ。
- デバッグ機能（章選択、フラグ・数値表示、全エンディング解放など）は URL に `?debug=1` を付けたときだけ有効にする。通常起動では存在が分からないようにする。
- 結夏が明示的に「ネタバレOK」と言うまで、このルールは解除しない。

## 表の設定（結夏も知っている範囲）

- ジャンル：廃校系パニック心霊ホラー。閉じた校舎で、仲間が一人ずつ欠けていく。段階的にクトゥルフ級まで怖くなる。
- 舞台：平成十八年（2006年）八月末。ダムに沈むことが決まった谷の村「鐘ヶ淵村」。残っているのは木造の村立鐘ヶ淵小学校と体育館だけ。九月一日の朝から湛水が始まる。谷は携帯の圏外。
- 主人公：先輩ちゃん（名前入力・24歳・修士2年）。背が高く、余裕のある美人。建築史から民俗学研究室に移ってきた、木造校舎の実測担当。
- 水無瀬 透（みなせ とおる）：22歳・学部4年・細い黒縁眼鏡。鐘ヶ淵村出身。研究室の古参で、先輩の案内役を命じられて不服そうについて回る。
- 調査隊：榊助教、小野寺千景、森岡大吾、日比野あゆみ、元用務員の宇津木。主人公と透を入れて七人。全員成人。
- 二人は初対面から始まる相棒。恋愛寄りだが、本編中は恋人にならない。性的な描写はしない。
- 形式：選択肢型テキストADV。グラフィックなし、テキストと演出のみ。全十章、マルチエンディング、途中死亡あり。

## 文体ルール

- 地の文は主人公視点だが、主人公を「私」「彼女」と書かない。主語を省いた語りにする。
- 主人公の発言はカギカッコで書かない。▷ から始まる「こういうニュアンスのことを言った」という間接話法の一文にする。選択肢の文言も同じ書き方にする。
- 冒頭の場面（第一章の書き出し）は結夏に提示済み。`docs/secret/opening.md` の冒頭原稿をそのまま使い、語尾や台詞を変えない。
- 登場人物は、特に理由がなければ普通に悲鳴を上げる。透も上げる。
- 透の口調・台詞の温度は裏設計書のサンプルに合わせる。毒舌・腹黒・小悪魔にしない。

## 技術仕様

- 素の HTML / CSS / JavaScript。ビルド不要で、`index.html` をブラウザで開けば遊べること。外部CDNは使わない（フォントも端末のもの＋CSSのフォールバックで対応）。
- 構成の目安：`index.html`、`css/`、`js/engine.js`、`js/scenario/ch01.js` 〜 `ch10.js`。シナリオはデータ（配列・オブジェクト）として書き、エンジンと分ける。
- 名前入力：タイトル後に入力。空欄なら既定の名前を入れる。本文中の主人公の名前は差し込みで表示する。
- セーブ／ロード：スロット3つ＋オートセーブ。`localStorage` に保存し、読み書きは try/catch で包む。保存に失敗しても遊べること。
- 既読スキップ、テキスト速度の変更、バックログ（直前数十行）を付ける。
- 途中で死亡した場合は、その章の最初からか直前の選択肢からやり直せる。
- タイトル画面にエンディング回収一覧を付ける。未回収は「？？？」表示。
- 音はデフォルトOFF。タイトル画面で切り替え。効果音は Web Audio で合成し、音声ファイルは使わない。
- スマホ幅（360px）でも崩れず、タップで読み進められること。キーボード（Enter / Space / 数字キーで選択）にも対応。

## 到達可能性の検証（必須）

- `docs/secret/` にある数値と分岐条件をもとに、全エンディングが通常プレイで到達できることを確かめる。各パラメータの最大値・最小値を計算し、閾値との余裕を `docs/secret/` 内のメモに残す。
- 裏設計書にあるモデルルートを `docs/secret/routes.json` に書き出し、選択を自動で流して到達エンディングを確かめるテストを `tests/run.js`（Node で `node tests/run.js`）として用意する。テストの出力はルート番号と合否だけにし、エンディング名を出さない。
- シナリオを変更したら毎回このテストを通す。

## ビジュアル方針

- 古い木造校舎の夜。暗い地に、チョークのような白い文字。
- 枠・状態欄・章題の見た目は、学校の備品を思わせるものにする。詳細な演出指示は裏設計書に従う。
- 派手なエフェクトより、じわじわ来る変化を優先する。演出は `prefers-reduced-motion` のときに控えめにする。

## 作業の進め方

1. `docs/secret/secret_design.md` を読む。
2. エンジン（表示・選択肢・名前入力・セーブ・回収一覧・デバッグモード）と第一章を作り、「第一章まで遊べる」とだけ報告する。
3. 一章ずつ追加する。各章の追加後にルートテストを流す。報告は技術的事実のみ。
4. 全章とエンディングが揃ったら、ルートテストの合否と「全エンディングに到達可能」であることだけを報告する。
