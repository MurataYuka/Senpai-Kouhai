# エンディング拡張 指示書（Claude Code用）

完成済みの『しずみがね』の一部のエンディングを拡張します。
設計は `docs/secret/ending_expansion.md` にあります。作業前に必ず読むこと。

## ネタバレ防止ルールの再適用

結夏は既存のエンディングをすべて見ていますが、拡張部分はまだ見ていません。CLAUDE.md のネタバレ防止ルールを、拡張部分について改めて適用する。

- 拡張する場面の中身・台詞・演出を、結夏への返答・コミット・ファイル名・識別子に出さない。
- どのエンディングを拡張しているかも、番号（`end_01` など）で報告する。エンディング名は書かない。
- 進捗報告は技術的事実のみ。結夏が拡張部分について「ネタバレOK」と言うまで解除しない。

## 表の方針（結夏も知っている範囲）

- 拡張するのは三つのエンディング。それぞれ、本編の一章の半分くらいの長さにする。
- ノーマルとバッドは変更しない。
- 既存の到達条件・分岐・数値は変更しない。
- 性的な描写はしない。

## 作業内容

1. `docs/secret/ending_expansion.md` を読む。`docs/secret/secret_design.md` のエンディングの節は、この資料で置き換えられたものとして扱う。
2. ch01〜ch10 の本文の文字数を数えて一章の平均を出し、拡張後の各エンディングの文字数が平均の45〜55%に収まるようにする。計測結果は `docs/secret/` 内のメモに残す。
3. 既存のエンジン・文体ルール（▷ の間接話法、主人公を「私」「彼女」と書かない）はそのまま使う。
4. 拡張部分に必要な演出（状態欄の書き込み、水位の変化、文字の大きさなど）を追加する。`prefers-reduced-motion` のときは控えめにする。
5. 変更後に `node tests/run.js` を流し、全ルートが従来どおりのエンディングに到達することを確かめる。
6. 報告は「エンディング `end_XX` の拡張が完了」「ルートテスト全件合格」「各エンディングの文字数（章平均比）」だけにする。
