# ADV エンジン テンプレート

文字だけで見せる選択肢型テキストADVのためのテンプレートです。ブラウザで動く HTML / CSS / JavaScript だけでできていて、ビルドは要りません。`index.html` をダブルクリックで開けば遊べます。

同梱のシナリオは動作確認用のダミー（2章、選択肢1つ、エンディング2つ、記録1件。ゲームオーバー機能をオンにすると、ゲームオーバー1件〈版A・版B〉と `@altopen` 1か所が加わる）です。

---

## フォルダ構成

```
adv-engine/
├─ index.html            … 画面の骨組み（ふつうは触らない）
├─ engine/               … エンジン本体（作品ごとには触らない）
│   ├─ core.js           … シナリオの解析と進行（node でも動く）
│   ├─ loader.js         … 起動：設定の点検とファイルの読み込み
│   ├─ ui.js             … 画面・操作・保存・音・演出の呼び出し
│   └─ engine.css        … 基本の見た目
├─ game/                 … 作品ごとに書くところ
│   ├─ config.js         … 設定（作品ID・ファイル一覧・パラメータ・エンディング…）
│   ├─ theme.css         … 見た目の上書き（枠・背景）
│   ├─ effects.js        … 演出の差し込み口
│   └─ scenario/         … シナリオ（ch01.js, ed01.js, records.js …）
├─ assets/bgm/           … 曲（無くても動く）
├─ tools/                … 点検用スクリプト（node）
├─ tests/                … モデルルートの自動テスト（node）
└─ .claude/launch.json   … Claude のプレビュー用（tools/serve.js を起動）
```

## 新しい作品を始める手順

1. **テンプレートをコピーする。** `adv-engine` フォルダを丸ごと新しい作品のフォルダにコピーする（例：`D:\works\新作\`）。
2. **作品IDを決める。** `game/config.js` の `id` を、その作品だけの値に書き換える（英数字・`-`・`_`）。
   - ブラウザに保存するもの（セーブ、既読、到達記録、記録、設定）は、すべて名前の頭に作品IDが付きます（例：`mywork.save01`）。
   - ローカルで開いた HTML どうしは保存場所を共有することがあるので、**作品IDを使い回すとセーブが混ざります。** 必ず作品ごとに変えてください。
   - `id` が空・未設定だと、起動時に「作品ID が設定されていません」と画面に出て止まります（点検スクリプトも同じく止まります）。
3. **設定を書く。** `game/config.js` の `title`・`files`・`vars`・`endings` などを作品に合わせる（各項目の説明はファイル内のコメント）。
4. **ダミーを消してシナリオを書く。** `game/scenario/` のダミーを消し、`config.files` に並べた名前でファイルを作る。`game/config.js` の最後の「ダミー専用」の行から下も消す。
5. **演出と見た目を書く。** `game/effects.js` と `game/theme.css`。使わない差し込み口は消してかまいません。
6. **テストを書き換える。** `tests/route_ed01.js` などを、作品のエンディングごとに用意する。
7. **点検する。** 下の「点検用スクリプト」を実行する。

## シナリオの書き方

### ファイルの形

1ファイル＝1章（または1エンディング）。**`ADV.add(...)` をファイルの1行目に書く**と、エラーや点検スクリプトの「行N」がファイルの行番号と一致します。

```js
ADV.add('ch01', `
// コメント（// で始まる行）と空行は無視される
@title 第一章|章題
本文の一行目。一行が一回のクリックで出る。
{name}さん、と名前を差し込める。
▷主人公の発言は、▷ から始まる一文で書く（色が変わって表示される）。
「ほかの人物の台詞はカギカッコで書く」
@next ch02
`);
```

- 名前は `config.files` に書いたもの（拡張子なし）と同じにする。
- ファイルの最後は必ず `@next` / `@goto` / `@end` で終える（無いと「本文が途切れています」エラー）。ゲームオーバーのファイルは `@over` で終える。
- 行頭が `@` `*` `+` `//` の文をそのまま出したいときは、行頭に `\` を付ける。
- `▷` の印は `config.selfMark` で変えられる（`''` で無効）。

### 命令

| 書き方 | 意味 |
|---|---|
| `@title 第一章\|章題` | 章題を画面中央に出す。`\|` の前はセーブ一覧と左上の表示にも使う。ページも改める |
| `@page` | 改ページ（テキストボックスを空にする）。あふれたときは自動でも改ページする |
| `*ラベル` | 飛び先の印 |
| `@goto ラベル` / `@goto ch02` / `@goto ch02:ラベル` | 移動 |
| `@next ch02` | 次の章へ（`@goto` と同じ。読みやすさのため） |
| `@end ed01` | エンディングの画面へ。到達記録が付く |
| `@set p1 += 2` / `@set p1 -= 1` / `@set p1 = 0` | パラメータを変える |
| `@if 条件` / `@elif 条件` / `@else` / `@endif` | 条件分岐（入れ子可） |
| `@choice` （＋選択肢の行） | 選択肢 |
| `@vis 名前 値` | 状態として残る見た目（セーブに入る）。下の「演出」参照 |
| `@fx 名前 引数` | 一時的な演出（スキップ中は省く）。組み込みは `shake`（枠と背景を揺らす）と `flash` |
| `@mark 名前 引数` | 作品側の `onMark` を呼ぶ（特定の行に来たときの処理） |
| `@bgm 名前` / `@bgm stop` | 曲を鳴らし始める／止める |
| `@record r01` | 記録を解放する（記録機能がオンのときだけ） |
| `@gameover g01` / `@gameover g01 b` | ゲームオーバーの版A（`b` を付けると版B）のファイルへ移り、その末尾でゲームオーバー画面へ。入った時点で回収記録が付く（ゲームオーバー機能がオンのときだけ） |
| `@over` | ゲームオーバーのファイルの終わり。ゲームオーバー画面へ（一覧からの再生なら一覧へ戻る） |
| `@altopen` | ゲームオーバー一覧の版の切り替えを解放する（版の切り替えがオンのときだけ） |
| `@自作の命令 引数` | `config.commands` に名前を書き、`effects.js` の `commands` に処理を書く |

条件式には、パラメータ名・数字・`< <= > >= == !=`・`&& || !`・`( )`・`+ - *` が使えます（例：`@if p1 >= 3 && p2 < p1`）。設定にない名前を書くと読み込み時にエラーになります。

### 選択肢

```
@choice
+ p1 > a | 一つ目の文面
+ p2+2 f1=1 > b | 二つ目の文面
+ - > ch05:c | 三つ目（パラメータが動かない）
+ p3 #A > d | タグ付き（テストで '#A' と指定して選べる）
```

- 書式は `+ 効果 > 飛び先 | 文面`。効果は空白区切りで、`p1`（＋1）、`p1+2`、`p1-1`、`p1=3`、`#タグ`。何も動かさないときは `-`。
- **表示の順番は書いた順のまま**です（毎回並べ替えることはしない）。並び順はデータの段階で決めてください。
- 選択肢のIDは自動で `ch01-c1`, `ch01-c2` … と振られる。`@choice q1` と書けば `ch01-q1` になる（行を足してもIDがずれない）。
- パラメータは `config.vars` に書いたものだけ使える。`min` / `max` を書くと、その範囲に丸める。

### 分岐と合流の約束

合流した後の共通の文には、どの分岐から来ても成り立つことだけを書き、分岐で違うことに触れたいときは `@if` の短い差し込み文にします。`node tools/seams.js` で継ぎ目を点検できます。

## エンディング

- `config.endings.main`：本編エンディング。エンディング一覧に並び、未回収は「？？？」。回収済みのものはタイトル画面の「エンディング一覧」から再生できる（到達したときの名前とパラメータで再生される）。
- `config.endings.extra`：追加エンディング。`extraUnlock` の条件を満たすと一覧に現れ、そこから再生する。条件は `'all-main'`（本編を全回収）、`['ed01', 'ed03']` のような配列、または `function (got) { ... }`。
- 到達記録はセーブとは別に保存される。

## 演出の差し込み方

### レイヤー

```
#back      テキストボックスの後ろ（大きな演出はここ）
  #bg        背景
  #fxLayer   作品の演出用（canvas や要素を自由に入れてよい）
  #dimmer    @vis dim on で暗くなる
#frame     画面の縁の枠（文字は入れない）
#game      本文（#box テキストボックス、#lines 本文、選択肢、メニュー）
```

**本文のテキストボックス（`#box`）と文字（`#lines`）は揺らさない。** 揺れ・傾き・明滅は `#frame` と `#back` にだけ付けてください。`#box` は `#frame` / `#back` の外にあるので、枠や背景を揺らしても文字は動きません。

### 見た目（game/theme.css）

`engine/engine.css` の後に読み込まれるので、ここで上書きします。色は `:root` の変数（`--bg` `--accent` `--box-bg` など）で変えられます。

`@vis 名前 値` を書くと `<body>` に `data-v-名前="値"` が付くので、CSS だけで状態ごとの見た目を作れます（値が `off` か空なら外れる）。

```css
body[data-v-bg="night"] #bg { background: #04060c; }
body[data-v-frame="alert"] #frame { border-color: #c44; }
```

### 処理（game/effects.js）

`window.ADV_EFFECTS` に書いた関数が呼ばれます。全部省略可。

| 名前 | 呼ばれるとき |
|---|---|
| `init(ctx)` | 起動時に一度 |
| `onReset(ctx)` | タイトルに戻る・新しく始める・ロードする前（演出を初期状態に戻す） |
| `onChapter(file, ctx)` | 章の開始時（はじめから、`@next`/`@goto` で別ファイルへ、エンディング再生） |
| `onRestore(ctx)` | ロードで状態を戻した直後 |
| `onParam(name, value, prev, ctx)` | パラメータが変わったとき（選択肢の効果・`@set`） |
| `onMark(id, arg, ctx)` | `@mark` の行に来たとき |
| `onText(text, ctx)` | 文が一行出るたび |
| `vis.名前(value, ctx)` | `@vis 名前 値` のとき。ロード時にも `ctx.restoring = true` で呼ばれる |
| `fx.名前(arg, ctx)` | `@fx 名前` のとき（スキップ中は呼ばれない） |
| `commands.名前(arg, ctx)` | 自作の命令のとき |

ゲームオーバー機能（下の節）を使うときは、次の三つも呼ばれます。

| 名前 | 呼ばれるとき |
|---|---|
| `onGameover(id, ver, ctx)` | `@gameover` に入ったとき（`ver` は `'a'` か `'b'`） |
| `onOverScreen(id, ver, ctx)` | ゲームオーバー画面を出したとき |
| `onAltOpen(ctx)` | `@altopen` に初めて到達したとき |

`ctx` の中身：`state` `vars` `file`（いまの状態。書き換えない）、`skipping`、`restoring`、`debug`、`replaying`（エンディング一覧・ゲームオーバー一覧からの再生中なら true）、`back` `bg` `layer` `frame`（各レイヤーの要素）、`shake()` `flash()`（枠と背景だけを揺らす／光らせる）、`toast(文)`。

**セーブに残すべき見た目は `@vis` で。** `@fx` と自作の命令の結果はセーブに入らず、ロードや `onReset` で消えます。

### 曲（追加エンディング用など）

- `@bgm 名前` を書いた行の次の文から鳴り始める（繰り返し再生）。`config.bgm.dir` + 名前 + `config.bgm.ext` の拡張子を順に試す（初期値 `assets/bgm/名前.mp3` → `.ogg` → `.wav`）。
- **止まるのは「はじめから」「ロード（直前の選択肢を含む）」「別のエンディングを開く」と `@bgm stop` のときだけ**で、`config.bgm.fadeMs` かけて小さくなって止まる。タイトルに戻っても、同じエンディングを開き直しても止まらない。
- 音源ファイルが無い・再生できないときは何もせず無音で続く（ブラウザの開発者ツールに 404 が出ることはある）。
- 音量スライダーと消音は「設定」画面にある。

## 記録（任意機能・初期状態はオフ）

話の進行で一件ずつ解放され、メニューとタイトル画面の「記録」から読める資料集です。

1. `config.records.enabled` を `true` にする。
2. `game/scenario/records.js` に中身を書く。識別子は `r01`, `r02` … の記号にする（内容が推測できる名前にしない）。
   ```js
   ADV.addRecords({
     r01: { title: '見出し', body: '本文。\n改行で段落を分ける。' }
   });
   ```
3. 解放したい行の前に `@record r01` を書く。

未解放は「？？？」。解放の記録はセーブとは別に保存されます。オフのときは `@record` は何もしません。

## ゲームオーバー（任意機能・初期状態はオフ）

本編の途中で、エンディングとは別枠の「ゲームオーバー」に入れる機能です。回収したものは「ゲームオーバー一覧」に溜まり、そこから再生できます。ゲームオーバー一つにつき版A・版Bの二つの中身を持てて、条件を満たすと一覧での再生を版Bに切り替えられます。**オフのままなら、既存の作品の動作は何も変わりません。**

### 設定（game/config.js）

```js
gameovers: {
  enabled: true,
  label: 'ゲームオーバー一覧',        // タイトル画面・メニューに出る一覧の名前
  screenText: 'GAME OVER',            // ゲームオーバー画面に出す文字
  retryLabel: '直前の選択肢からやり直す',
  list: [
    // id：識別子（g01, g02 …）／ a：版Aのファイル名 ／ b：版Bのファイル名（省略可。無ければ版Aを使う）／ title：一覧に出す名前
    { id: 'g01', a: 'g01a', b: 'g01b', title: '見出し' },
  ],
  alt: {
    enabled: true,                    // 版の切り替えを使うか
    toA: '版Aを見る',                  // 版Bを見ているときのボタンの文言
    toB: '版Bを見る',                  // 版Aを見ているときのボタンの文言
  },
},
```

- 文言はすべて作品ごとに変えられます。
- `list` の各ファイル（`a` / `b`）は `config.files` にも並べてください（読み込みは他のシナリオと同じ）。
- 起動時（と点検スクリプト）に設定を点検し、`list` が空、識別子が `g01` の形でない・重複している、`title` が無い、`a` / `b` のファイルが `files` に無い、エンディングと同じ名前、同じファイルを二か所で使っている、などは画面にエラーを出して止まります。

### シナリオ

```
@choice
+ p1 > a | 進む
+ - > bad | 引き返す

*bad
@gameover g01
```

- `@gameover g01` で版Aの、`@gameover g01 b` で版Bのファイルへ移り、その末尾でゲームオーバー画面に出ます。**本編中にどちらの版を流すかは、この書き方で決まります**（一覧の切り替えの状態とは関係ない。一度解放したあと「はじめから」遊んでも、序盤は序盤の版のまま流れる）。
- `@altopen` に到達すると、版の切り替えが解放されます（一度解放したら、新しく始めても解放されたまま）。
- ゲームオーバーのファイルは、エンディングと同じく1ファイルで完結させ、最後を `@over` で終えます（`@end` とは別）。
  ```js
  ADV.add('g01a', `
  @title 途中|見出し
  本文。{name} も @vis / @fx / @bgm / @mark などの命令も使える。
  @over
  `);
  ```
- 読み込み時のエラーになるもの：機能がオフなのに `@gameover` / `@over` / `@altopen` を書いた、版の切り替えがオフなのに `@altopen` を書いた、`list` にない識別子、`b` の無い項目に `@gameover g01 b`、`@over` の無いゲームオーバーのファイル（「本文が途切れています」）、ゲームオーバーのファイルの中の `@choice` / `@end` / `@next` / `@gameover` / 別のファイルへの `@goto`、ゲームオーバーのファイル以外での `@over`。

### ゲームオーバー画面とやり直し

- ゲームオーバーのファイルを読み終えると、`screenText` の画面に移ります。ボタンは `retryLabel`（直前の選択肢からやり直す）と「タイトルへ」。
- やり直しは直前の選択肢セーブ（`ID.qsave`）をロードします（ロードと同じ扱いなので、曲はフェードして止まる）。その回でまだ選択肢が一度も出ていない位置でのゲームオーバーなら、「はじめから」と同じ動き（名前入力から）になります。
- **回収の記録は、画面に着いた時点ではなく `@gameover` に入った時点で付きます**（途中でタイトルに戻っても回収済み）。版A・版Bのどちらで到達しても同じ識別子の回収です。
- スキップ中にゲームオーバーに入ると、未読と同じく止まります。既読の判定は他のファイルと同じです。
- ゲームオーバーのファイルの中では手動セーブできません（メニューの「セーブ」が押せなくなる）。

### 一覧と版の切り替え

- タイトル画面とメニューに `label` の項目が出ます（`enabled: true` のときだけ）。
- `list` の順に並び、未回収は「？？？」、回収済みは `title`。見出しに回収数（例：`ゲームオーバー一覧　3 / 12`）が出ます。
- 回収済みを選ぶと単体で再生し、終わるとゲームオーバー画面ではなく一覧に戻ります。名前とパラメータは到達したときのもの（エンディング再生と同じ扱い）。
- 版の切り替え（`alt.enabled: true`）：
  - `@altopen` に到達するまでは、一覧の再生は版Aだけで、切り替えボタンは出ません（存在が分からないように）。
  - 解放後は版Bが基本になり、一覧の上に切り替えボタンが出ます。版Bを見ているときの文言が `alt.toA`、版Aを見ているときが `alt.toB` で、押すたびに一覧全体の表示版が入れ替わります。
  - `b` の無い項目は、どちらの状態でも版Aを再生します。

### 見た目と演出

- ゲームオーバー画面の要素には `.ov-scr`（画面）`.ov-mark`（文字）`.ov-row`（ボタンの並び）`.ov-retry` `.ov-title`（ボタン）のクラスが付き、画面には `data-go="g01"` と `data-ver="a|b"` が付くので、`game/theme.css` で版ごと・項目ごとに見た目を変えられます。一覧の切り替えボタンは `.ov-alt`、解放後の一覧の本体には `data-ver` が付きます。
- `game/effects.js` の `onGameover` / `onOverScreen` / `onAltOpen`（「処理」の表を参照）。`ctx.replaying` で一覧からの再生かどうかが分かります。

### 保存

`ID.overs`（回収記録）、`ID.alt`（切り替えの解放）、`ID.altView`（一覧でいま見ている版）。どれもセーブとは別です（下の「保存」の表）。

### 点検とテスト

`tools/reach.js` がゲームオーバーの到達と `@altopen` を、`tools/count.js` がゲームオーバーの文字数（目標 `config.tools.targets.gameover`、版A・版B別）を報告します。`seams.js` / `choices.js` / `tone.js` もゲームオーバーのファイルを対象に含みます。テストは `tests/route_g01a.js`（ゲームオーバーのルート）と `tests/over_list.js`（一覧と版の切り替え）。詳しくは「点検用スクリプト」の節。

### ダミーでの動作確認

テンプレートのダミーは、設定を切り替えるだけでゲームオーバーを試せるようにしてあります。

1. `game/config.js` の `gameovers.enabled` と `gameovers.alt.enabled` を `true` にする。
   - ファイルの最後の「ダミー専用」の数行が `g01a` / `g01b` を `files` に足し、ダミーの `ch01` の選択肢に三つ目（版Aのゲームオーバー）と四つ目（版Bのゲームオーバー）が、`ch02` に `@altopen` が出ます。
2. `node tools/reach.js`、`node tests/run_all.js` などを実行する（「到達テスト：5/5 通過」になる）。ブラウザで `index.html?debug=1` を開いて遊んでも確かめられます。
3. 終わったら両方 `false` に戻す（オフでは「到達テスト：2/2 通過（省略 3）」）。

作品を始めるときは、`config.js` の「ダミー専用」の行から下と、ダミーのシナリオ（`g01a.js` / `g01b.js` を含む）を消してください。ダミーの `ch01` / `ch02` の中の `${...}` は、オンとオフを一つのファイルで切り替えるためのダミー専用の書き方で、作品では使いません。

## 保存

`localStorage` に、作品IDを頭に付けた名前で保存します。読み書きはすべて try/catch で囲んであり、使えない環境でも（その回の間だけ覚えて）遊べます。

| 名前 | 中身 | 消えるとき |
|---|---|---|
| `ID.save01`〜`ID.save11` | 手動セーブ（`config.saveSlots` で数を変更可） | |
| `ID.qsave` | 直前の選択肢セーブ（選択肢が出るたびに自動） | |
| `ID.ends` | エンディングの到達記録 | セーブとは別 |
| `ID.read` | 既読（ファイル名と文面から作った鍵） | セーブとは別 |
| `ID.records` | 記録の解放 | セーブとは別 |
| `ID.overs` | ゲームオーバーの回収記録 | セーブとは別 |
| `ID.alt` | 版の切り替えの解放 | セーブとは別 |
| `ID.altView` | ゲームオーバー一覧でいまどちらの版を見ているか | セーブとは別 |
| `ID.opt` | 音量・消音・前回の名前 | |

- 既読は文面で判定するので、行を足したり消したりしても他の行の既読はずれません（文面を直した行は未読に戻ります）。
- セーブは「ファイル名と位置」で持つので、シナリオを大きく書き換えると古いセーブが別の場所から始まることがあります。

## 点検用スクリプト

node で実行します（作品のフォルダで）。結果が長いときは `--out ファイル名` で UTF-8 のファイルに書き出せます。

### 継ぎ目の書き出し

```bash
node tools/seams.js
```

選択肢と `@if` ごとに、分岐ごとの「分岐の文 → 合流後の文」を並べます。ファイル名を付けるとそのファイルだけ（`node tools/seams.js ch03`）。ファイルをまたぐ合流も見つけます。合流後に次の `@if` が来たら、そこで止めて別の継ぎ目として並べます。`--before 3 --after 4` で前後の行数を変えられます。

### 文字数

```bash
node tools/count.js
```

章・エンディングごとに本文（地の文・台詞・選択肢の文面。空白を除く）を数え、目標の範囲に入っているかを報告します。目標は `config.tools.targets`（初期値：本編 7000字・エンディング 3500字・追加エンディング 6000字・ゲームオーバー 1500字、±15%）。その場で変えるときは `--main 8000 --tolerance 0.1` など（ゲームオーバーは `--gameover`）。ゲームオーバーのファイルは版Aと版Bを別々に報告し、版ごとの合計も出します。範囲外があれば終了コード 1。

### 地の文の語の一覧

```bash
node tools/tone.js
```

カギカッコ（「」『』）の外で「敬語」「口調」「声で」「調子で」を含む行を、その語を【】で囲んで一覧にします。語は `config.tools.toneWords` か `--words 敬語,口調`。

### 選択肢の文面の被り

```bash
node tools/choices.js
```

全選択肢を一覧にし、似ている組（文面の2文字組の一致率が `config.tools.similar` 以上、または片方がもう片方を含む）を「同じ選択肢内／同じ章／別の章」の区別つきで並べます。`--similar 0.4` で基準を変えられます。

### 到達の確認

```bash
node tools/reach.js
```

選択肢を総当たりして（同じ地点・同じパラメータの組は一度だけ）、次を報告します。

- 各パラメータの取りうる最小値・最大値（通常プレイ）
- 各本編エンディングに到達できるか。できるものは選び方の例と、テストにそのまま使える `picks` を表示
- 追加エンディングの解放条件が満たせるか、単体で最後まで再生できるか
- 設定にないエンディングへの到達、一度も通らないファイル、進行エラー
- ゲームオーバー機能がオンのとき（`@gameover` は行き止まりとして扱う）：
  - 各ゲームオーバーの版A・版Bに通常プレイで到達できるか。できるものは選び方の例と `picks` を表示
  - `list` にあるのにどの版にも到達できないもの（×）、版Bが本編で一度も使われない項目（△。一覧の切り替えでだけ見られる）
  - 各ゲームオーバーのファイルを単体で `@over` まで再生できるか
  - `@altopen` に到達できるか（版の切り替えがオンのとき）
  - ゲームオーバーを避けたときの本編エンディング到達（上のエンディングの到達は、すべてゲームオーバーを通らない道筋で見つけたもの）
  - 参考として、この先がゲームオーバーだけになる選択肢の地点

到達できないエンディング・ゲームオーバーや問題があれば終了コード 1（△は問題に数えない）。状態が多すぎるときは `--max` で上限を変えられます。

### モデルルートの自動テスト

```bash
node tests/run_all.js
```

`tests/route_*.js` と `tests/over_*.js` をすべて実行し、「到達テスト：N/N 通過」と表示します（ゲームオーバー機能がオフのときは、ゲームオーバーのテストを「省略 N」として数えから外す）。ルートの無いエンディング・ゲームオーバーも知らせます。1本だけなら `node tests/route_ed01.js`。

本編エンディングのルート（`tests/route_ed01.js`）：

```js
'use strict';
const { route, runMain } = require('./lib');
const spec = { ed: 'ed01', picks: [0, 'p2', '#A'], vars: { p1: 1 } };
module.exports = () => route(spec);
module.exports.spec = spec;
runMain(module);
```

- `picks`：出てくる選択肢を順に、数字（上から何番目か、0始まり）／`'#タグ'`／パラメータ名（そのパラメータを動かす選択肢）で指定。`{ 'ch01-c1': 0, ... }` のように選択肢IDで指定してもよい。
- `rest`：`picks` に無い選択肢の選び方（例：`rest: 'p1'`）。省略すると、指定が足りないときにテストが失敗する。指定が余っても失敗する。
- `vars`：着いたときのパラメータ（書いたものだけ確かめる）。

追加エンディングのルート（`tests/route_ed07.js` など）：

```js
'use strict';
const { extraRoute, runMain } = require('./lib');
module.exports = () => extraRoute('ed07');
runMain(module);
```

本編のルートで順に回収していったとき、条件を満たす前は解放されず、満たしたときに解放され、単体で最後まで再生できることを確かめます。

ゲームオーバーのルート（`tests/route_g01a.js` など。ゲームオーバー機能がオフのときは「省略」になる）：

```js
'use strict';
const { overRoute, runMain } = require('./lib');
const spec = { go: 'g01', ver: 'a', picks: [2], vars: { p1: 0 } };
module.exports = () => overRoute(spec);
module.exports.spec = spec;
runMain(module);
```

- `go`：着くはずのゲームオーバーの識別子。`ver`：`'a'`（省略時）か `'b'`。`picks` / `rest` / `vars` / `name` は本編のルートと同じ。
- 指定の版のファイルの `@over` に着くこと、回収の記録がゲームオーバーのファイルに入った時点（最初の文より前）で付くことを確かめる。

ゲームオーバー一覧のテスト（`tests/over_list.js`）：版の切り替えの解放前は版Aだけでボタンが出ないこと、解放後は版Bが基本でボタンの文言が `alt.toA`、押すと版Aになり文言が `alt.toB` になること、`b` の無い項目はどちらでも版Aを再生すること、各項目を単体で `@over` まで再生できること、本編のルートで `@altopen` に着き前後で再生版が A → B に変わることを確かめます。画面（`engine/ui.js`）は一覧の版とボタンを `ADV.overView` / `ADV.overPlayVer` / `ADV.overFile` で決めているので、このテストがそのまま画面の出し分けの確認になります。

ファイル名・選択肢ID・ラベル・パラメータ名・`@vis` / `@fx` / `@mark` の名前・記録とゲームオーバーの識別子・CSS クラスなどは、中身が推測できない記号にすることをおすすめします（`ch01`、`ed01`、`p1`、`m1`、`r01`、`g01`、`g01a` / `g01b` など）。ゲームオーバーの版の呼び名も「A / B」で通し、意味のある語を付けないでください。対応表は作品側の非公開メモに書いてください。
